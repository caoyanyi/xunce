# 能力目标

将现有“对话后执行一批任务”的原型升级为可管理、可恢复、能解释结果的测试工作台。用户可先规划与修订任务，再选择执行；不同会话排队，当前运行有明确进度；提问不启动测试，停止后可以继续未完成任务。

# 已核实的问题

- `classifyMessage` 将所有未匹配文本视为自动探索执行，包括一般疑问。
- 任务只有创建接口，没有编辑、停用、归档和批量选择界面；新规划只按标题合并，不淘汰过时任务。
- 全局只有一个运行槽，其他会话返回冲突；界面只知道当前会话状态。
- 设置只有发送对话后才保存；对话内容被用作会话名称。
- 汇总使用全会话任务状态，无法区分本次运行和过去结果；缺少失败步骤和可操作诊断。
- TesterArmy 对非 loopback HTTP 目标有上游限制，规则任务没有兼容选择。
- 轮询可能取消尚未完成的上一轮请求；复跑后详情可能继续显示人为选择的旧记录。

# 约束

- 保留 Node/Fastify/SQLite/React、三个执行器、Docker 部署和所有网卡访问。
- 单个浏览器 worker 顺序执行；新增跨会话 FIFO 队列，不同时执行多个浏览器任务。
- 任务执行必须经过权限、作用域和执行器配置检查；保存交互任务草稿不代表授权执行。
- 普通问答、状态、帮助、停止不能启动新的浏览器或模型请求。
- 不自动识别图形验证码，不自动重试具有写入风险的动作。手动输入继续使用同一浏览器会话。
- 所有旧记录保持可读；归档与停用可恢复，不删除历史；排队和运行中的会话禁止修改其任务定义。
- 服务重启后标记排队/执行中的作业中断，不自动恢复可能执行写入的任务。
- 测试使用本地页面和模拟模型边界，不使用真实账号或模型额度。

# 实施与验收

## U1 对话和目标

增加解释、重新规划、继续未完成任务等明确意图；保留会话测试目标，控制命令不覆盖目标/名称。问答结合真实状态解释只读、验证码、模型配置和失败原因，不启动作业。补充命令和 API 回归测试。

## U2 任务资产与历史

增加任务修订、启停、归档与恢复；新规划原子替换过期的自动任务，保留手动/已编辑任务。运行保存当时的任务版本与步骤。界面提供结构化步骤编辑、新建和批量选择。验证编辑冲突、历史不变、非法步骤与权限检查。

## U3 作业队列与继续运行

增加持久化作业记录、每次运行计数、活动任务、排队顺序与 `/api/runtime`。每会话只允许一个未完成作业，跨会话 FIFO；排队可取消；停止后“继续”跳过已完成任务。验证排队、取消、异常释放、关闭、重启恢复与人工输入状态。

## U4 设置和运行预检

增加会话名称、目标和选项的独立保存接口。任务启动前检查交互权限与模型配置；规则任务在非 loopback HTTP 使用 Playwright 并说明兼容原因。明确显示活动会话与队列，不再只返回“已有任务运行”。

## U5 结果和恢复体验

显示本次作业进度/计数、失败步骤、诊断与建议、任务版本；执行日志不重复写出可能含凭据的完整 AI 指令。复跑自动显示最新记录。改为请求完成后再安排下一轮轮询，避免慢请求被持续取消。

## U6 验证与交付

更新中英文文档和验证记录。运行相关回归、完整单元/集成测试、浏览器 E2E、类型/lint/构建和依赖审计；检查差异与秘密；构建 Docker 并在没有活动/排队作业时更新服务。保留数据卷。提交并推送代码。

# 这轮边界

不引入多租户、定时调度、跨浏览器矩阵、远端 worker、自动解验证码或自动迁移登录状态。队列与编辑先解决现有单机平台的可用性，不增加运维服务。
