## 代码复查与已处理问题

在主线程按正确性、接口契约、权限边界、恢复能力、依赖和用户流程分别复查，遵守本次 AGENTS 指令要求的顺序执行。

1. 修复 TesterArmy 首次响应等待发生于页面创建前的问题，并按上游实际报告 schema 提取失败原因。
2. 为生成的执行文件解析实际模块地址，避免自定义 `DATA_DIR` 位于仓库外时模块无法加载；下载的测试模板仍使用标准 npm 导入。
3. 同源导航任务实际点击链接并等待目标页面，不只验证链接文本。
4. 浏览器 context 创建失败或运行取消时仍关闭 browser；视觉调用传入取消信号；子进程有超时与进程组终止。
5. SQLite 重启恢复保留历史，并处理 run 已提交、task 状态尚未更新的中断窗口。
6. 区分“有哪些失败任务”与“复跑失败任务”；界面和服务共用指令分类，查询不会意外启动复跑。“自动发现任务并执行”也不会被误判为只探索。
7. 初次探索未产生任务时也显示停止按钮；补充对应界面 E2E。
8. 模型规划失败时，对话明确说明保留的是 DOM 基础任务；任务详情展示 DOM / 模型 / 手动来源。
9. 密钥只由服务端环境读取。API 输入校验、参数化 SQL、HTTP(S)/凭据校验、同源导航、只读请求约束、Host/Origin 检查、报告 HTML 沙箱/下载均已落实。
10. 固定关键上游版本，升级有漏洞的传递依赖并保存 lockfile；复查凭据与动态执行入口，没有发现真实密钥或模型代码执行入口。

## 使用边界

当前验收范围为本机、单用户、单进程、单 worker。真实视觉模型业务效果、跨域认证、加密登录态、多租户、容器网络隔离、调度和分布式 worker 留在后续规划。TesterArmy 的非 loopback 明文 HTTP 约束来自当前上游；内网 HTTP 测试可选择 Playwright。

平台状态“已完成”表示调度结束，通过与失败由任务计数独立展示；演示商城的一项失败是预期验证结果。

## 本地运行观察

`GET /api/health` 应返回 `{"status":"ok"}`。正常任务经 `discovering → running → completed`，停止经 `cancelled`，基础设施错误经 `failed`。问题排查先看会话执行日志和单个 run 的原始报告；未通过的任务可单独复跑。服务端错误保留在控制台日志，不向 API 返回堆栈。无生产部署或第三方资源变更。
